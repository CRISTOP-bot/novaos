# M2.3 — process context y address space

Esta etapa separa las responsabilidades sin afirmar aislamiento de memoria que el paging actual todavía no implementa.

## Estado

- `nova_process` posee PID, estado, padre, tarea y un `nova_address_space`.
- `nova_task` posee contexto de scheduler, referencia a su proceso y `nova_user_context` (`RIP`, `RSP`, `RFLAGS`, `CS`, `SS` y registros generales).
- `nova_process_current()` devuelve el proceso activo; `GETPID` consulta esa interfaz.
- `SYS_EXIT` guarda el estado de salida en el contexto del proceso y marca el proceso activo como terminado.
- El self-test crea un proceso Ring 3 de prueba, lo activa, ejecuta la transición Ring 3/syscall y restaura el proceso kernel.

## Limitación deliberada

El paging actual mantiene un único root global y no expone todavía un constructor seguro de tablas ni una operación CR3 por proceso. `nova_address_space` es por tanto una propiedad explícita del proceso, pero sus instancias usan temporalmente el mapeo kernel compartido (`NOVA_ADDRESS_SPACE_KERNEL_SHARED`). `nova_address_space_switch()` valida esta condición; no simula un cambio de CR3.

No se implementan todavía ELF, address spaces aislados, copy-on-write, copy_from_user, user stack real, `exec` ni `waitpid`. El siguiente milestone debe reemplazar el root compartido por roots clonados con el mapeo kernel necesario y probar los permisos antes de cargar un ELF.
