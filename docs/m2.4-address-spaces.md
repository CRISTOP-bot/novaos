# M2.4 — Per-process paging roots

M2.4 introduce un root de page tables por proceso sin cargar todavía un ELF.

## Diseño

- El root kernel sigue siendo el creado por `paging_init()`.
- `paging_root_create()` reserva un PML4 nuevo, copia únicamente las entradas de la mitad superior (kernel/HHDM) y deja vacía la mitad inferior para mappings privados.
- `paging_root_map_page()` y `paging_root_translate()` operan sobre un root concreto sin cambiar el CR3 activo.
- `paging_root_switch()` cambia el root activo y ejecuta `mov cr3`.
- Al destruir un root se liberan sus tablas de la mitad inferior y el PML4; las tablas superiores compartidas y las páginas hoja no se liberan.

## Seguridad y límites

La copia de entradas superiores preserva el acceso a kernel text/data, HHDM, GDT/IDT/TSS y stacks del kernel. Las tablas superiores se comparten de forma deliberada; por eso todavía no se permite modificar mappings kernel desde un address space de proceso. La mitad inferior es privada y el self-test coloca el mismo VA en dos roots con páginas físicas diferentes.

Todavía no se implementan permisos consultables por `paging_translate`, `copy_from_user`, ELF, stack de usuario ni un cambio de address space desde un scheduler de procesos. Esas piezas pertenecen a la siguiente fase.
